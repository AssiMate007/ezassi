# EzAssi — Fixes (June 11, 2026)

## What was broken

### 1. Writer could not upload completed assignment file
**Root cause:** Two issues stacked:
- File names with spaces, parentheses, accents, or special characters were being passed
  raw into the Supabase storage path. Supabase storage URL-encodes them, but RLS still
  evaluated them against the raw path, and any character outside `[a-zA-Z0-9._-]` could
  trip the storage policies — silently failing the upload.
- **Old RLS policies from the very first migration (`Involved see file row`,
  `Writer uploads file`, `Writer replaces own file`, `Admin releases file`) still
  existed on `public.assignment_files`** and still called `public.has_role()`. The
  "definitive_fix" migration only dropped policies under their newer alias names, so
  these stale policies stayed and silently blocked uploads when `has_role()` returned
  NULL or threw.

### 2. No admin flow to approve payment without screenshot / no manual control
**Root cause:** Admin panel previously only showed a "Confirm" button when the student
had already uploaded a screenshot. If the student forgot, you were stuck. Also the
writer was getting a misleading "send ₹X payout to writer" notification (sent to the
writer themselves!).

## What was fixed

### Database / Supabase (apply once via SQL editor)

Apply **`supabase/migrations/20260611000003_complete_reset_and_storage_bucket.sql`**.
It is safe to re-run.

It does:
- **Drops EVERY existing policy** (by dynamic loop) on `profiles`, `user_roles`,
  `assignments`, `bids`, `payments`, `assignment_files`, `notifications`,
  `chats`, `messages`, and `storage.objects` so no stale `has_role()` policy remains.
- **Recreates a clean policy set** using a direct sub-query against `user_roles`
  (`EXISTS (SELECT 1 FROM public.user_roles WHERE user_id = auth.uid() AND role='admin')`)
  instead of `has_role()` — so policies never depend on a grantable function.
- **Creates the `assignment-files` bucket** automatically if it doesn't exist, sets it
  private, allows up to 30 MB.
- **Adds storage SELECT policy for admin to read student screenshots** (previously the
  admin couldn't open uploaded payment screenshots because the storage policy only
  matched the uploader's folder).
- **Adds `is_banned` column** to `profiles` (idempotent).
- **Adds tables to the realtime publication** so the admin dashboard live-updates.
- **Guarantees the owner email `assimate007@gmail.com` has the `admin` role**.

### Frontend (already committed in this PR)

`src/routes/_app.payment.$id.tsx`
- Sanitizes writer-upload filenames: strips path separators, collapses whitespace, and
  whitelists `[a-zA-Z0-9._-]` before building the storage path.
- Sanitizes screenshot extensions too.
- Sets `contentType` on uploads (helps `signedUrl` downloads serve correct MIME).
- Surfaces the real Supabase error message in the toast (instead of a generic
  "Upload failed") so you can debug in production.
- Blocks empty (0-byte) writer uploads.

`src/routes/_app.admin.tsx`
- New **"Manually approve"** button for payments stuck in `awaiting_payment` without
  a screenshot — confirms after a JS `confirm()` prompt so you can't fat-finger it.
- New banner shows `N payments pending — student hasn't uploaded screenshot` so you
  see them at a glance.
- Removed the bogus "send ₹X payout to writer" notification that was being sent to
  the writer themselves; replaced with a friendly "Job complete!" notification.
- Sort logic now keeps no-screenshot rows above already-paid rows so you can act on
  them quickly.

## How to apply

1. **In Supabase SQL editor**, paste and run
   `supabase/migrations/20260611000003_complete_reset_and_storage_bucket.sql`.
2. **Pull this repo** in Lovable / your editor — the TypeScript changes will take
   effect on the next deploy.
3. Log in as the admin (`assimate007@gmail.com`) — you should now see the shield tab.
4. Test the full loop:
   - Student posts assignment → writer bids → student accepts → student starts
     payment → student uploads screenshot.
   - Admin confirms (or **manually approves** if no screenshot).
   - Writer uploads completed file — **this is the bug we fixed; should now succeed
     even with weird filenames**.
   - Admin releases file → student downloads.
